# MSL 성능 변경 및 인게임 확인

## 적용 내용

- 거래 예약·송금·보상·사망·접속 종료의 즉시 저장은 유지한다. 거래 정산 완료 저장만 최대 약 2초간 모아서 처리한다. 이 구간에 서버가 종료되면 디스크에 먼저 저장한 예약을 기존 접속 복구 경로에서 재정산한다. 일반 장비 스냅샷은 10초, 거래 확인은 기존 1초, 주기 저장은 기존 60초다.
- UID별 계정 인덱스를 캐시한다. 인덱스와 UID를 확인하므로 계정 배열을 교체해도 잘못된 계정을 반환하지 않는다.
- MSL 점령 판정 사용 중 기존 KP 판정을 중복 실행하지 않는다. Arma 3 2.18 이상에서는 원형 영역 조회에 탑승자를 포함하고 기존 수평 거리·고도·의식 상태·장갑차 조건으로 필터링한다. 구버전은 기존 전역 탐색으로 자동 복귀한다.
- 전선 연결 계산은 점령 목록 또는 본진 위치가 바뀔 때만 한다. 마커를 유지하고 추가·삭제·고립 색상 변경만 전파한다.
- 개인 스탯과 판매 권한은 값이 바뀔 때만 전파한다. 판매 권한 배열을 복사하여 원본 계정 변경이 마지막 전파 값까지 바꾸는 것을 방지한다.
- 보급 상자는 삭제 시점에 사람이 근처에 있으면 30초마다 재확인한다. 실제 KP 자원 상자는 기존 KP 관리에 맡긴다. 헬기 정리는 등록된 정리 대기 목록만 순회한다.
- AI의 최근접 표적 선택은 전체 정렬 대신 한 번 순회한다. 조사 병력 파견은 그룹 한도를 채우면 추가 시야 검사를 중단한다. 상점은 처치 수만 바뀌었을 때 목록을 다시 만들지 않는다. 클라이언트의 기지 액션 조건은 0.5초간 결과를 공유하며 서버 거래 검증은 매번 실행한다.

영역 조회의 탑승자 옵션과 도입 버전은 [Bohemia nearEntities 문서](https://community.bohemia.net/wiki/nearEntities), 높이 제한 없는 원형 영역은 [inArea 문서](https://community.bohemia.net/wiki/inArea)에 따른다.

## 검증 상태

`python3 tools/verify_msl.py --sqflint-path /tmp/msl-sqflint`로 SQF 문법 분석, 함수 등록과 기존 통합 검사를 실행한다. `git diff --check`로 공백 오류를 확인한다. 엔진을 실행한 FPS 측정이나 멀티플레이 합격 판정은 이 환경에서 수행하지 않았다. 정적 분석기는 명령 인자의 엔진 동작까지 검증하지 않는다.

## 인게임 실행

테스트 미션의 서버 로컬 디버그 콘솔에서 실행한다. 원격 실행으로 호출하지 않는다.

```sqf
[] execVM "tools\msl_selftest.sqf";
[] execVM "tools\msl_performance.sqf";
```

성능 도구는 60초간 5초 간격으로 해당 머신의 FPS와 유닛·차량·활성 섹터 수를 RPT의 `[MSL PERF]`에 기록한다. 이어 활성 섹터별로 기존/신규 후보 탐색 시간과 결과 차이를 `[MSL PERF QUERY]`에 기록한다. 점령 타이머, 계정, 장비, 저장 파일은 변경하지 않는다. HC에서 실행하면 그 HC 수치를 기록한다.

탐색 시간은 단일 조회의 마이크로벤치마크이므로 FPS 개선율로 해석하지 않는다. `missingUnits`, `extraUnits`, `missingArmor`, `extraArmor`가 비어 있는지 확인한다. 모드가 만든 agent/특수 모듈 등이 차이로 잡히면 해당 객체가 실제 점령 대상인지 검토한다.

동일한 모드·서버 설정에서 변경 전후를 비교하고, 평시와 여러 섹터 동시 교전 때 각각 측정한다. 점령은 탑승자, 고지대 병력, 의식불명 병력, 중심부 잔적, 가동 가능한 적 장갑차를 포함해 확인한다. 거래는 정산 완료 전 서버 종료 후 재접속 시 중복 지급/차감 없이 복구되는지 테스트용 프로필로 확인한다. 전선 색상은 점령/상실 및 JIP 접속에서 확인하고, 보급품은 정리 시점에 근처에 있던 플레이어가 떠난 뒤 삭제되는지 확인한다.
