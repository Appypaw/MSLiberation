# MS Liberation PvE 캠페인 변경

## 적용 범위

`scripts/msl/config.sqf`의 `MSL_enabled = true`로 새 기능을 사용합니다.
기존 파일을 교체하기 전에 서버 프로필과 미션 PBO를 백업하세요.
새 미션을 PBO로 만들어 전용 서버에서 검증한 뒤 운영에 적용해야 합니다.
이 저장소에는 Arma 3 실행 환경이나 모드 바이너리가 없어 엔진/멀티플레이 검증은 아직 하지 않았습니다.

## 개인 경제

- 개인 창고 없음. UID별 자금, XP, 처치/사망/점령/누적 판매액, 현재 장비와 판매 권한을 서버 프로필에 저장합니다.
- 기지 반경 100m / FOB 반경 50m에서 보급소 이용. 송금과 개인 해금 진행도는 본진 단말기에서만 이용할 수 있습니다. 송금 수신자는 접속 중인 아군이며 현장에 있어도 수신 가능합니다.
- 기존 무기고 액션이 개인 상점으로 연결됩니다. 기존 무기고 및 리스폰 저장 장비의 무료 복원 경로는 차단합니다.
- 무료 보급은 에디터에 배치된 같은 역할의 초기 장비를 사용합니다. 장착 조준기·소음기·레이저·양각대·NVG를 제거하며, 역할의 기본 무기/방탄복/의료품은 유지하고 연막/케미라이트 2개씩을 추가합니다.
- 무료 보급을 선택하면 현재 장비 전체를 교체합니다. 구매품/노획품도 사라지므로 확인 창을 표시합니다.
- 해금은 XP에 따른 영구 구매 권한입니다. `MSL_levelThresholds`에 설정한 누적 XP에서 레벨이 올라갑니다. 무기별 가격·해금은 `presets/msl/custom_weapons.sqf`와 [전체 가격표](MSL_WEAPON_PRESET.md)를 따릅니다. 미지정 무기의 기본값은 권총 $500/Lv1, 소총 $1200/Lv2, 발사기 $2500/Lv4이며, 부착물·장비·의상은 아래 장비 티어를 사용합니다. 클래스별 가격·레벨은 `MSL_priceOverrides`로 변경합니다.
- 상점은 현재 커스텀 프리셋에서 실제 로드된 공개 클래스만 취급합니다. 내부/접힌/사용 후/부착물 세트 총기는 구매 목록에서 제외합니다. 다른 색상·총열·구경·레일·개머리판은 유지합니다.
- 새 무기/의복/가방은 해당 슬롯을 비운 뒤 구매합니다. 단품 액세서리는 수납 공간에 지급하며 인벤토리에서 장착합니다. 기존 장비를 자동 폐기하거나 창고에 넣지 않습니다.
- 적 시체와 시체의 의복/가방, 죽으면서 떨어진 무기에서 가져온 장비에 판매 권한을 기록합니다. 무료 지급에는 판매 권한이 없습니다. 같은 클래스도 실제 노획 기록이 있으면 판매할 수 있습니다.
- 판매가는 구매가의 35%. 탄창은 실제 제거된 탄약 비율로 정산합니다. 총은 탄창/부착물 분리 후 판매, 비어 있는 의복/가방도 판매할 수 있습니다. 장착 부착물은 개별 판매 가능합니다.
- 구매품에도 재판매 권한을 부여합니다. 판매 권한은 인물에게 귀속되므로 친구에게 건넨 장비의 판매 권한까지 자동 이전하지는 않습니다. 송금은 지원합니다.
- 사망 시 휴대 장비/판매 권한을 잃고 무료 보급으로 재출격합니다. 자금/XP는 유지합니다. 생존 재접속 시 마지막 휴대 장비를 복원합니다.
- 구매·판매 중에는 인벤토리를 잠시 잠급니다. 서버가 제안한 장비 변경을 관측한 뒤 거래를 확정합니다. 연결 중단 시 미완료 거래를 저장해 재접속 후 다시 적용합니다.
- 송금은 서버에서 한 번에 차감/입금하고 저장합니다. 음수/소수/잔액 초과/자기 자신/비아군 송금을 거부합니다. RPT에 거래를 기록합니다.
- 기본 개인 자금은 $1500. 적 처치 10 XP, 점령 참여 $350/150 XP. 실제 보상/가격은 설정에서 조정 가능합니다.

## 점령·전선

- 모든 지역을 자유롭게 점령할 수 있습니다. 별도 공격 방향 선택 UI/인접 점령 제한 없음.
- 제압 범위는 최소 350m이며 중심 확보 범위는 45m입니다. 아군 병력 수가 많다는 이유로 남은 적을 무시할 수 없습니다.
- 잔적 1~2명: 아군이 지역 내에 있고 적 장갑차가 없는 제압 상태를 연속 450초(7분30초) 유지해야 합니다. 동시에 적이 없는 중심 45m 확보 60초도 충족해야 합니다.
- 적이 3명 이상으로 늘거나 아군이 지역을 이탈하면 제압 시간이 초기화됩니다. 중심 이탈/중심 적 진입은 중심 확보 시간을 초기화합니다.
- 적을 완전히 소탕했다면 중심 확보 60초만 요구합니다. 마지막 1~2명을 반드시 찾아야 하는 문제를 긴 안정화 시간으로 대체합니다.
- 제압 범위의 적 전투 가능 장갑차/전차는 점령을 막습니다. 사망/포로/ACE·AIS 의식불명 병력, 고공 항공기 승무원은 제외합니다.
- 지역 중심 사이 2500m 이내를 연결합니다. 본진 인근 아군 지역에서 이어지지 않은 곳은 고립 거점입니다. 본진이 해상/먼 곳일 때 가장 가까운 아군 지역 하나를 연결 출발점으로 사용합니다.
- 지도에 전선/고립 아이콘을 표시합니다. 이는 연결 거리로 계산한 전황 표시이며 실제 지형·도로 기반 경계선은 아닙니다.
- 고립 거점에 정기적으로 생성하던 습격은 제거했습니다. 후방 위험은 기존 적 순찰·군수망과 요청형 Evac의 착륙장 노출로 표현합니다.

## 적군과 기반시설

- 주둔군/정규군은 기존 분대를 유지하고, 주요 도시/군사기지에 준비도 40 이상일 때 특작군 분대를 확률적으로 편성합니다.
- 로드된 PRACS SLA Especas 병종을 탐색합니다. 누락 시 검증된 후보 또는 정규군으로 대체합니다.
- 특작군은 탐지한 적에게 측면 이동을 시도합니다. 플레이어 위치를 강제로 AI에 공개하지 않습니다.
- 고정익은 CAS/CAP 목록을 분리합니다. CAP는 아군 항공기가 비행 중일 때 출격하며 항공 표적만 지시합니다. CAS는 발견한 지상 표적을 공격합니다.
- 동적 파일런 지원 기체는 호환 탄약의 `airLock`으로 무장을 구분합니다. 구형 고정 무장 기체는 기존 내장 무장을 유지합니다. 실제 PRACS/RHS 비행/무장 적합성은 모드 로드 후 확인해야 합니다.
- 공수 증원은 수송헬기 목록을 사용합니다. 공격헬기를 무작위로 고르다 수송헬기를 찾지 못하는 무한 루프를 제거했습니다.
- 타워는 이제 파괴 가능하며 파괴 상태를 별도 저장합니다. 파괴/점령 시 해당 타워의 아직 출발하지 않은 지역 증원을 차단합니다. 이미 이동 중인 적은 사라지지 않습니다.
- 공장·군사기지 점령률에 따라 증원 대기 증가, 전투단 축소, 순찰 생성 지연, 중장비/항공 투입 감소가 적용됩니다.
- 기존 수송대 탈취 보조 임무 완료 시 추가 군수 압박 20%(최대 60%)를 적용합니다. 압박은 30초마다 0.5%p 회복합니다.
- 적 비행 스폰 주변 1200m 이내 군사기지를 점령하면 해당 출격 지점을 사용할 수 없습니다.

## AI 공중보급

- 액션 메뉴에서 탄약/의료/팀 자원을 요청합니다. 서버 전체 15분 재사용 대기시간, 동시 비행 1대입니다.
- PRACS C-130 → RHS C-130J → 바닐라 수송 VTOL 순서로 설치된 기체를 사용합니다.
- 요청 위치 120m 이내에 요청 이후 신호를 발사/투척합니다. 낮에는 연막, 밤에는 플레어 또는 케미라이트를 인정합니다. 자신의 실제 발사체만 인정합니다.
- 신호 대기는 180초. 수면/구역 밖 신호, 신호 소멸, 조종사/기체/요청자 사망은 투하 취소 사유입니다.
- 신호를 확인하면 새 직선 접근 경로로 비행해 실제 기체 위치에서 낙하산 상자를 투하합니다. 물품을 플레이어 앞에 순간 생성하지 않습니다.
- 탄약은 요청자의 현재 주무기/권총 탄창, 의료는 기본 및 로드된 ACE 의료품, 자원은 착지 후 KP 보급/탄약/연료 상자로 지급합니다.
- 주변에서 보급 지점을 관측하거나 수송기를 인지한 서버 소유 적 순찰이 접근합니다. 통신망과 군사기지가 살아 있으면 추가 병력이 실제 적 기지에서 출발합니다. 적을 투하 지점 옆에 생성하지 않습니다.
- 기존 순찰 재지정은 그룹을 소유한 서버/HC에서 실행합니다. 새 증원·고립 거점 습격은 서버에서 관리합니다.
- 기체는 귀환 후 정리하고, 보급 표식은 15분 후 제거합니다. 근처에 플레이어가 없는 일반 보급상자도 정리합니다. KP 자원 상자는 기존 캠페인 관리에 맡깁니다.

## 저장 및 되돌리기

- 기존 KP 저장 형식은 변경하지 않습니다. 별도 서버 프로필 키: `GRLIB_save_key + "_MSL_V1"`.
- 거래 즉시, 사망/접속 종료 시, 평시 60초 간격 저장. 타워 파괴·수송대 피해도 저장합니다.
- 기존 두 저장 삭제 파라미터를 동시에 켜면 MSL 프로필도 초기화합니다.
- `MSL_enabled = false`로 새 캠페인 기능을 끌 수 있습니다. 기존 무기고 프리셋 정리와 함수명 오타/빈 타워 반환/헬기 무한루프 수정은 유지됩니다.

## 검증 방법

오프라인 검사:

```sh
python3 tools/verify_msl.py --sqflint-path /tmp/msl-sqflint
```

검사기는 새 SQF와 변경된 실행 코드의 분석, 함수 등록/파일 연결, 기존 무기고의 비무기 섹션 보존을 검사합니다.
대규모 정적 무기고 배열은 분석기 성능 문제로 엔진 코드 분석에서 제외하고 섹션 보존을 검사합니다.
이 검사는 엔진 실행이나 모드 클래스 실재 여부를 증명하지 않습니다.

테스트 미션의 **서버 로컬** 디버그 콘솔:

```sqf
[] execVM "tools\msl_selftest.sqf";
```

RPT의 `[MSL TEST RESULT]`에서 24개 인벤토리/계정·점령·진행도 검증 결과를 확인합니다.
최신 클래스 추출은 `tools/export_mod_weapons.sqf`, 모드/설정 사전 점검은 `tools/msl_preflight.sqf`를 사용합니다.

전용 서버와 클라이언트 2명 이상에서 아래를 반드시 확인해야 합니다.

1. 초기 지급·사망 3회·재접속·서버 재시작: 자금/XP 유지, 사망 장비 소실, 생존 장비 복원.
2. 같은 물건 구매/판매 버튼 연타, 거래 중 연결 종료, 재접속: 이중 지급·이중 환불·이중 판매 없음.
3. 무료 장비 판매 거부. 같은 클래스 적 노획품은 판매. 시체/가방/낙하 무기, 빈/부분 탄창, 장착 부착물, 가방 속 총을 각각 확인.
4. 송금 두 클라이언트 동시 실행, 잔액 초과/음수/소수/자기 송금 거부, 합계 잔액 보존.
5. 공중에 있는 아군만으로 점령되지 않음. 완전 소탕 시 중심 확보 60초, 잔병 1~2명은 450초 제압과 중심 확보 60초를 모두 요구, 적 증원 시 제압 타이머 초기화.
6. 후방 지역 점령 가능. 고립 표시 생성/연결 후 해제. 적 반격으로 상실 가능.
7. 증원 대기 중 타워 파괴/점령: 새 출동 취소. 파괴 상태 재시작 유지.
8. 공장/군사기지 점령 및 수송대 탈취 전후 증원 대기·규모·항공 출격 감소.
9. CAS 지상 공격, CAP 공중 요격, 미설치 기체 처리, 비행장 상실, 기체 정리.
10. 낮 연막/밤 플레어·케미라이트, 타인 신호, 수면/구역 밖/무신호, 요청자/조종사 사망, 동시 보급 요청.
11. 실제 상자 낙하/착지·내용물·자원 상자 회수, 주변 적 관측/접근과 원거리 증원.
12. HC 연결/해제, JIP, AIS 소생, ACE 유무 및 다수 플레이어에서 RPT 오류·서버 FPS 확인.

## 본진 단말기 / 해금 설정

단말기는 모니터 형태의 어두운 패널, 금색 강조선, 좌측 탭으로 구성합니다.
장비 구매·판매는 장비 이미지/가격/해금 레벨을 표시합니다. 개인 진행도는 XP 막대, 6개씩 넘기는 레벨 카드, 해금/잠김 표시와 레벨별 품목 수를 표시합니다.
해금 카드의 품목 버튼을 누르면 그 레벨의 장비만 상점에서 조회합니다. 본진 밖에서는 송금/진행도 탭을 비활성화하고, 열린 상태로 본진을 벗어나면 닫습니다. 송금은 서버에서도 본진 위치를 재검증합니다.

설정 예시 (`scripts/msl/config.sqf`):

```sqf
// 레벨 1=0XP, 2=800XP, 3=2000XP, 4=4000XP ... 누적 XP
MSL_levelThresholds = [0,800,2000,4000,7000,11000];
MSL_levelTitles = ["RECRUIT","OPERATOR","SPECIALIST","VETERAN","ELITE","LEGEND"];
// 카테고리 전체 또는 정확한 클래스 하나의 구매 권한 해금 레벨
MSL_unlockRules = [["weapon_pistol",1],["weapon_rifle",2],["weapon_launcher",4],["optic",2],["suppressor",3],["nvg",5],["armor",2],["item",1],["magazine",1],["backpack",1],["goggles",1],["rhs_weap_m4a1",3]];
// 가격과 해금 레벨을 함께 덮어쓰는 가장 높은 우선순위
MSL_priceOverrides = [["rhs_weap_m4a1",1800,3]];
```

XP 배열은 0으로 시작하는 엄격한 오름차순이며 각 해금 레벨은 설정한 최대 레벨 이내로 지정합니다. 설정 변경 후 미션을 재시작합니다. 실제 로드되지 않은 클래스는 품목 수에 포함하지 않습니다.

## 방어 웨이브와 독택

- 정기 방어 작전은 없습니다. 대도시 점령/FOB 신설 사건에 확률적으로 연결합니다. 세부 흐름은 `docs/MSL_SCENARIOS.md`를 참고하세요.
- 대도시 점령 35%, 신설 FOB 30%를 기본 확률로 사용하고 적 군수 약화에 비례해 감소합니다. 큰 방어 작전은 동시 1개, 시작 사이 최소 45분 간격입니다.
- 신설 FOB는 기존 저장에서 로드한 FOB를 제외합니다. 경고 후 공격부대 출발까지 건설 기준 약 5~10분입니다. 실제 도달 시간은 거리와 AI 경로에 따라 늘어납니다.
- 거점 방어는 60초 준비 후 10~20분 무작위 시간 동안 유지하는 방식입니다. 웨이브 전멸을 요구하지 않습니다. 남은 시간과 적 병력 상한에 따라 증원이 접근합니다.
- 성공 시 현장에 120초 이상 참여하고 정산 때 살아서 600m 이내에 있는 인원에게 $650/250XP를 지급합니다.
- 후방 Evac은 액션 메뉴로 요청합니다. 본진에서 실제 헬기가 출발해 안전한 착륙장에 접근하고, 90초 탑승 대기 후 실제 탑승 인원을 본진으로 수송합니다. 순간이동은 없습니다.
- 기존 KP 수송대 탈취/적 FOB 수색/조종사 구출의 발동·승리 조건은 유지합니다. 대도시 점령 직후의 강제 반격만 새 확률 이벤트로 대체하며, 일반 KP 순찰/반격은 유지합니다.
- 적 시체를 3m 이내에서 바라보면 **적 독택 회수** 액션이 나타납니다. 실물 아이템 없이 $100/30XP를 즉시 지급하고 개인 독택 수를 기록합니다.
- 시체당 서버에서 한 번만 회수 가능하며 다른 플레이어가 이미 회수했다면 액션이 사라집니다. 거리·생존·아군 여부·적 시체 여부를 서버에서 검증합니다. `MSL_dogtag*`로 보상/거리를 변경합니다.

추가 실서버 확인: 방어 웨이브 출발/교전/성공·실패·이탈·상한 도달, 두 클라이언트의 같은 시체 독택 동시 회수, 본진 밖 송금 요청 거부, 본진 이탈 시 진행도 닫힘, 해금 규칙을 바꾼 뒤 서버 구매 검증과 카드 표시 일치, 해상·건물 위 점령 범위와 타이머 초기화.

단말기 시각 배치, AI 경로, 동시 독택 회수는 실제 Arma 3에서 아직 검증하지 않았습니다.


## 무기고와 스폰 변경

- 새 프로필 및 사망 후에는 `MSL_spawnUniform` 전투복만 착용한다. 살아서 재접속한 경우 저장 장비를 복원한다.
- 무기고의 해금 장비 탭에는 현재 레벨로 구매 가능한 장비만 표시한다. 각 행에 가격과 필요 레벨, 상단에 현재 잔고가 표시된다. 검색으로 최대 200개 표시 제한 밖의 장비를 찾을 수 있다.
- 무료 키트 탭에서 CETME, HK33, M16A2, M60, SAAWS 대전차, Stinger 대공 키트를 선택한다. 모든 병과에서 사용 가능하며 키트 수령은 현재 장비 전체 교체다. 확인 후 수령하며 기존 장비를 보관하거나 환불하지 않는다.
- 무료 키트 무기는 유료 구매 목록에서 제외한다. 무료 장비에는 판매 권한이 생기지 않는다.
- `MSL_freeKits`에서 무기와 발사기를 설정한다. 서버는 실제 설치된 클래스와 호환 탄창을 확인해 키트를 생성한다. 무기나 탄약이 없으면 키트 수령을 거절한다.
- 이 화면은 무기고 상자에서 여는 MSL 전용 구매 화면이다. 기본 BIS 가상 무기고의 3D 착장 화면은 아직 연결하지 않았다.

실게임 확인: 첫 접속/사망 스폰, 재접속 복원, 여섯 키트별 탄창 로딩과 잔탄/수납량, SAAWS HEAT 및 Stinger 락온, 수령 취소, 무료 장비 판매 차단, 레벨 상승 후 목록 갱신, 구매/송금 후 잔고 갱신을 dedicated 서버와 클라이언트에서 확인해야 한다.
